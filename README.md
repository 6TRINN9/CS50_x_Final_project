# 🎬 CINEMA BOOKING — Система бронирования билетов

Веб-приложение для бронирования билетов в кинотеатр с **защитой от race condition**
на основе гибридного хранилища **PostgreSQL + Redis**.

## 🎯 Ключевая фича — борьба с Race Condition

Когда два пользователя одновременно пытаются занять одно место:
- **Redis `SETNX`** (SET if Not eXists) атомарно резервирует место
- **TTL 10 минут** автоматически освобождает неоплаченные места
- **Lua-скрипты** гарантируют атомарность операций освобождения
- **PostgreSQL** — источник истины для постоянных данных

```
┌──────────┐         ┌─────────┐         ┌──────────────┐
│  Client  │ ──────▶ │  Flask  │ ──────▶ │   Redis      │ (SETNX + TTL)
└──────────┘         │   API   │         └──────────────┘
                     │         │ ──────▶ ┌──────────────┐
                     └─────────┘         │ PostgreSQL   │ (source of truth)
                                         └──────────────┘
```

## 🚀 Быстрый старт

### 1. Клонировать и перейти в папку
```bash
git clone <repo-url>
cd cinema-booking
```

### 2. Поднять PostgreSQL и Redis
```bash
docker-compose up -d
```

### 3. Создать виртуальное окружение
```bash
python -m venv venv
source venv/bin/activate      # Linux/Mac
# или: venv\Scripts\activate  # Windows
```

### 4. Установить зависимости
```bash
pip install -r requirements.txt
```

### 5. Настроить окружение
```bash
cp .env.example .env
# при необходимости отредактировать .env
```

### 6. Заполнить БД тестовыми данными
```bash
python seed.py
```

### 7. Запустить приложение
```bash
python app.py
```

Открыть в браузере: **http://localhost:5000**

## 🧪 Тестирование race condition

Откройте два браузера (или инкогнито-окно) под разными пользователями,
выберите один и тот же сеанс и одновременно кликните на одно место.

Один пользователь получит место, второй — уведомление «Место занято».

## 🛡️ Архитектурные решения

| Проблема | Решение |
|---|---|
| Два клиента резервируют одно место | Redis `SETNX` — атомарная операция |
| Резерв "зависает" навсегда | TTL 600 сек — автоудаление |
| Клиент платит за чужое место | Проверка владельца через Lua-скрипт |
| Рассинхрон Redis ↔ PG | Lua-скрипты для атомарных проверок |
| Билет создан, но Redis-ключ истёк | При оплате проверяем TTL/владельца |
